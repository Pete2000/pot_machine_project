# 安卓上位机第一轮联调脚本

这份脚本只服务一件事：

`先把安卓上位机的通信骨架、状态轮询、参数块写入和 PLC 基础响应跑通。`

第一轮不追求完整订单自动化，也不追求所有异常都测满。

---

## 1. 测试目标

按下面顺序验证：

1. 安卓上位机能启动 `ModbusWorker`
2. 安卓上位机能稳定轮询 PLC 状态
3. 心跳 `M400` 能按周期翻转
4. 只读状态区时，地址和功能码正确
5. 写加热参数区时，PLC 能收到
6. 写应急补水参数区时，PLC 能收到
7. 最后再写相位命令区

---

## 2. 测试前提

测试前确认：

1. PLC 串口参数已经和安卓设置页一致
2. 从站地址确认无误
3. PLC 已下载当前正式逻辑
4. Android 上位机已能打开应用并进入主界面
5. 使用正式地址和协议：
   - [plc-final-formal-spec.md](D:/Users/achillesniu/Documents/自研打锅机项目/docs/plc-final-formal-spec.md)
   - [ladder-logic-sketch-generic.md](D:/Users/achillesniu/Documents/自研打锅机项目/docs/ladder-logic-sketch-generic.md)

---

## 3. 第一阶段：只读验证

这一阶段只验证“能读通”，先不要写相位和工艺命令。

### 3.1 读温度和液位

读取：

- `D200 ~ D214`

预期：

1. 能拿到返回帧
2. `D200 / D201` 有温度值
3. `D210` 有液位状态值
4. 安卓 UI 或日志能看到这组数据

如果失败，优先检查：

1. 串口号
2. 波特率
3. 校验位
4. 从站地址
5. `03` 功能码

### 3.2 读输入输出镜像

读取：

- `M300 ~ M339`

预期：

1. 能读到按钮、输入、输出镜像位
2. 按下现场按钮时，安卓侧状态会变化
3. 某个输出动作生效时，镜像位也会变化

如果失败，优先检查：

1. `01` 功能码
2. `M` 区地址换算
3. PLC 镜像逻辑是否已做

---

## 4. 第二阶段：心跳验证

### 4.1 写心跳位

写入：

- `M400`

节奏：

1. 第 1 秒写 `1`
2. 第 2 秒写 `0`
3. 第 3 秒写 `1`

预期：

1. PLC 能看到心跳翻转
2. 安卓轮询不中断
3. PLC 不进入心跳超时故障

如果失败，优先检查：

1. `05` 功能码
2. `M400 = 0x0190`
3. PLC 心跳判定周期

---

## 5. 第三阶段：加热参数区验证

这一阶段先不测真实加热动作，只测：

`安卓能不能把参数正确写进 PLC。`

### 5.1 保存加热参数

写入：

- `D340 ~ D349`

建议测试值：

- `commandId = 2001`
- `commandType = 10`
- `heaterSelect = 1`
- `targetTemp = 55`
- `hysteresis = 3`
- `sensorSelect = 0`

预期：

1. PLC 侧对应寄存器有值
2. PLC 如果做了回显状态区，`D350 ~ D359` 会更新
3. 不要求这一步就真正开加热

### 5.2 开启加热总使能

写入：

- `D340 ~ D349`

建议测试值：

- `commandId = 2002`
- `commandType = 11`

预期：

1. PLC 接收加热总使能
2. 如果当前温度低于下限且安全允许，主/备某一路才真正打开
3. 如果液位超低或急停，则参数可以收下，但输出不应真正开启

### 5.3 关闭加热总使能

写入：

- `D340 ~ D349`

建议测试值：

- `commandId = 2003`
- `commandType = 12`

预期：

1. PLC 撤销加热总使能
2. 实际加热输出关闭

---

## 6. 第四阶段：应急补水参数区验证

### 6.1 保存应急补水参数

写入：

- `D360 ~ D369`

建议测试值：

- `D360 = mode = 2`
- `D361 = timedDuration = 30`
- `D362 = sparePumpMode = 0`

注意：

- 应急补水参数区不是命令握手区，不写 `commandId / commandType`。
- 如果把 `mode = 2` 错写到 `D362`，PLC 会误认为 `sparePumpMode = 2`，导致备用泵参与骨膏输出。

预期：

1. PLC 能收到模式和时长
2. `D370 ~ D379` 能回显当前状态
3. 这一阶段先不要求现场按钮已经触发

### 6.2 点动模式验证

步骤：

1. 安卓把模式保存为 `Jog`
2. 现场按 `X03`
3. 读取：
   - `M300 ~ M339`
   - `D370 ~ D379`

预期：

1. 按下时 `Y07` 动作
2. 松开时 `Y07` 关闭
3. 状态区能反映 `Jogging`

### 6.3 时控模式验证

步骤：

1. 安卓把模式保存为 `Timed`
2. 保存时长，例如 `30`
3. 现场按 `X03`

预期：

1. `Y07` 按时长动作
2. 到时自动关闭
3. 状态从 `TimedRunning` 回到 `Idle`

---

## 7. 第五阶段：相位命令区最小验证

这一阶段才开始碰真正的相位命令。

### 7.1 单相位最小写入

写入：

- `D300 ~ D315`

建议测试值：

- `commandId = 1001`
- `commandType = 1`
- `jobSlotMask = 1`
- `D303 = 10`
- `D304 = 0`
- `D305 = 0`
- `D306 = 0`
- `D307 = 1`
- `D308 = 0`
- `D309 = 0`
- `D310 = 1`

预期：

1. PLC 接收新相位命令
2. `D320 ~ D329` 状态更新
3. 只有一条当前物理位水路动作
4. 相位结束后出现 `Completed`

### 7.2 带辅料的最小相位

建议测试值：

- `commandId = 1002`
- `commandType = 1`
- `jobSlotMask = 2`
- `D303 = 26`
- `D304 = 0`
- `D305 = 0`
- `D306 = 0`
- `D307 = 2`
- `D308 = 10`
- `D309 = 14`
- `D310 = 2`

预期：

1. 当前左上服务逻辑 `2` 号位
2. 水、鸡油、骨膏按当前相位逻辑执行
3. 相位结束后 `finishedCommandId = 1002`

---

## 8. 安卓侧观察点

第一轮联调时，安卓侧至少要观察：

1. 当前通信配置是否正确加载
2. 当前 PLC 状态是否从 `Connecting` 进入 `Connected`
3. 最新轮询快照是否在刷新
4. 心跳有没有持续翻转
5. 写命令后状态区是否有对应变化
6. 失败时 `lastMessage` 是否能反映问题

---

## 9. 第一轮联调通过标准

满足下面这些，就说明我们可以进入下一阶段：

1. 安卓能稳定轮询，不掉线
2. 心跳位正常
3. `D200 ~ D214` 可读
4. `M300 ~ M339` 可读
5. `D340 ~ D349` 可写
6. `D360 ~ D369` 可写
7. `D300 ~ D315` 可写
8. `D320 ~ D379` 可读并反映 PLC 状态

---

## 10. 当前不建议第一轮就测的内容

先不要一开始就测：

1. 真实订单全自动解析到相位
2. 多次转锅完整流程
3. 全量手动锅型/锅底界面联动
4. 所有故障码和恢复策略

第一轮只要把：

`轮询 + 心跳 + 参数块写入 + 单相位执行`

跑通，就已经很有价值了。
