这份文档解决的是第二层问题：

`业务动作 -> PLC 线圈 / 寄存器 / 读状态`

原则：
1. 已被地址表直接证明的内容，按已确认处理。
2. 需要从点位名称和现场控制规则反推的内容，明确标为“当前执行推断”。
3. 这份文档先服务于安卓主控联调，不替代 PLC 程序最终说明书。

## 1. 当前执行层的基本理解

当前项目先按下面这套理解：

1. `出水阀0 -> 出水口1 -> 左上`
2. `出水阀1 -> 出水口2 -> 右上`
3. `出水阀2 -> 出水口3 -> 左下`
4. `出水阀3 -> 出水口4 -> 右下`

这条对应关系来自“4 个出水口”和 `0~3` 阀编号顺序的联合推断。
当前状态：
`当前执行推断`

## 2. 通讯保活动作

### 动作：心跳

目标：
告诉 PLC 安卓主控仍在线。

PLC 写入：
1. 线圈 `M400`
2. 地址 `0x0190`

执行方式：
1. 每 1 秒写一次
2. 值在 `1 -> 0 -> 1 -> 0` 之间交替

当前状态：
`已确认`

## 3. 水路控制动作

### 动作：单锅加水

业务含义：
4 个出水口同时给同一种锅底加水。

当前执行推断：
1. 打开进水阀 `M106 / 0x006A`
2. 同时打开出水阀 `M102 ~ M105 / 0x0066 ~ 0x0069`
3. 保持 `addWater` 对应时长
4. 到时后关闭 `M102 ~ M105`
5. 最后关闭 `M106`

配方来源：
`potCode + potTypeCode -> addWater`

当前状态：
`进水阀和 4 个出水阀地址已确认；具体“先关谁后关谁”属于当前执行推断`

### 动作：拼锅左侧加水

业务含义：
左侧锅底对应左上和左下两口。

当前执行推断：
1. 打开进水阀 `M106 / 0x006A`
2. 打开出水阀 0 和 2
   `M102 / 0x0066`
   `M104 / 0x0068`
3. 保持左侧锅底 `addWater` 时长
4. 关闭对应出水阀
5. 关闭进水阀

当前状态：
`左侧对应 1+3 已确认；阀 0/2 与 1/3 槽位映射为当前执行推断`

### 动作：拼锅右侧加水

业务含义：
右侧锅底对应右上和右下两口。

当前执行推断：
1. 打开进水阀 `M106 / 0x006A`
2. 打开出水阀 1 和 3
   `M103 / 0x0067`
   `M105 / 0x0069`
3. 保持右侧锅底 `addWater` 时长
4. 关闭对应出水阀
5. 关闭进水阀

当前状态：
`右侧对应 2+4 已确认；阀 1/3 与 2/4 槽位映射为当前执行推断`

### 动作：四宫格单槽加水

业务含义：
某一个槽位单独加对应锅底的水。

当前执行推断：
1. 打开进水阀 `M106 / 0x006A`
2. 只打开目标槽对应的一个出水阀
3. 保持该锅底 `addWater` 时长
4. 关闭该出水阀
5. 关闭进水阀

对应关系当前按下面处理：
1. 左上 -> `M102 / 0x0066`
2. 右上 -> `M103 / 0x0067`
3. 左下 -> `M104 / 0x0068`
4. 右下 -> `M105 / 0x0069`

## 4. 辅料控制动作

### 动作：鸡油加料

业务含义：
当 `addChickenOil > 0` 时，为当前位于左上辅料工位的锅位加鸡油。

当前执行推断：
1. 先确保目标锅位已经处于左上工位
2. 将鸡油时长写入 `D212 / 0x00D4`
3. 打开鸡油泵 `M109 / 0x006D`
4. 保持到设定时长结束
5. 关闭鸡油泵

当前状态：
1. 鸡油泵控制位已确认
2. `D212` 为鸡油时间寄存器已确认
3. “自动模式是否也复用 D212 这组时间寄存器”属于当前执行推断

### 动作：骨膏加料

业务含义：
当 `boneOil > 0` 时，为当前位于左上辅料工位的锅位加骨膏。

当前执行推断：
1. 先确保目标锅位已经处于左上工位
2. 将骨膏时长写入 `D214 / 0x00D6`
3. 打开骨膏泵 `M110 / 0x006E`
4. 保持到设定时长结束
5. 关闭骨膏泵

当前状态：
1. 骨膏泵控制位已确认
2. `D214` 为骨膏时间寄存器已确认
3. “自动模式是否也复用 D214 这组时间寄存器”属于当前执行推断

## 5. 人工转锅相关动作

### 动作：提示人工转锅

业务含义：
非左上锅位需要鸡油或骨膏时，暂停自动流程，提示人把目标锅位转到左上。

安卓侧动作：
1. 弹窗提示
2. 暂停后续 PLC 写入
3. 等待人工确认

PLC 侧当前理解：
1. 这一步本身不必强制写 PLC 动作位
2. 只是停止继续下发水路/辅料动作

当前状态：
`已确认需要人工转锅；是否要专门占用 PLC 某个暂停位，暂未确认`

### 动作：人工确认转锅完成

当前确认实现：
1. 安卓界面弹窗点击确认
2. 当前不结合实体按钮 `M302`

当前状态：
1. `M302` 这个输入点已确认存在
2. 但当前正式流程只使用 UI 弹窗确认

## 6. 应急动作

这些动作主要来自物理按钮输入。

### 动作：应急加水

读取输入：
`M303 / 0x012F`

当前执行推断：
1. 安卓检测到按钮触发
2. 打开进水阀
3. 根据当前选定逻辑或预设时长执行对应出水动作

当前状态：
`只确认了输入点；应急加水究竟走哪一套时长与目标槽规则，仍待现场二次确认`

### 动作：应急鸡油

读取输入：
`M305 / 0x0131`

当前执行推断：
1. 写入 `D212`
2. 打开 `M109`
3. 到时关闭 `M109`

### 动作：应急骨膏

读取输入：
`M304 / 0x0130`

当前执行推断：
1. 写入 `D214`
2. 打开 `M110`
3. 到时关闭 `M110`

## 7. 读状态动作

### 动作：读取按钮区状态

用于：
1. 急停检测
2. 加水按钮
3. 传锅完成
4. 应急操作

当前建议：
安卓定时轮询 `M300 ~ M305` 及后续需要的按钮组。

### 动作：读取输出状态

用于：
1. 核对阀门是否真的动作
2. 核对鸡油泵、骨膏泵状态
3. 做 UI 实时显示

当前建议：
安卓定时轮询 `M320 ~ M330`。

### 动作：读取温度与液位

读取寄存器：
1. `D200 / 0x00C8`
2. `D201 / 0x00C9`
3. `D210 / 0x00D2`

液位最低建议：
1. `0` 时禁止加热相关动作
2. 液位异常时 UI 明确报警

## 8. 当前最适合安卓端实现的动作原子化

为了让后面代码更好写，安卓端可以先把动作拆成这些原子操作：

1. `setCoil(address, on)`
2. `setRegister(address, value)`
3. `pulseHeartbeat()`
4. `fillSlots(slots, durationMs)`
5. `dispenseChickenOil(durationMs)`
6. `dispenseBonePaste(durationMs)`
7. `awaitManualRotateConfirm()`
8. `readButtons()`
9. `readOutputs()`
10. `readSensors()`

## 9. 当前仍待后续确认的动作细节

1. 自动加水时，进水阀与出水阀的开关先后顺序是否有硬性要求。
2. 自动加鸡油/骨膏时，是否必须先写时间寄存器，再开泵，还是 PLC 内部已有封装逻辑。
3. `单独出水阀 M107` 在正式业务里什么时候用。
4. `喷雾阀 M108` 在正式业务里什么时候用。
5. `主加热器 M100`、`备加热器 M101` 是由安卓控，还是 PLC 自主闭环。
6. 物理“加水按钮”和安卓界面“加水按钮”是否最终走同一条执行链。
7. 人工转锅完成是否必须绑定物理按钮 `M302`。

## 10. 当前阶段的最佳理解

如果先不追求最终定稿，只为了把项目控制主链路跑通，当前最合理的执行理解是：

1. 心跳独立持续写入 `M400`
2. 水路动作主要靠 `M102 ~ M106`
3. 鸡油动作主要靠 `D212 + M109`
4. 骨膏动作主要靠 `D214 + M110`
5. 读状态主要靠 `M300 ~ M330 + D200/D201/D210`
6. 人工转锅是安卓流程控制，不是 PLC 自动旋转控制

## 11. 防飞溅执行补充

1. 同一轮加水允许多个锅位同时启动。
2. 但停止必须按各锅位的独立配方时间分别关闭对应出水口。
3. 如果当前左上锅位已经在执行鸡油或骨膏，而另一个非左上锅位也需要鸡油或骨膏，则该非左上锅位本轮不能同时参与辅料。
4. 结合最新确认，这类非左上锅位连加水也必须延后，不能先参与本轮统一加水。
5. 等当前左上锅位辅料完成后，安卓暂停流程并提示人工转锅。
6. 转锅确认后，再为该非左上锅位执行加水和鸡油或骨膏，并允许这三类动作在该相位内一起启动，避免飞溅。
7. 如果当前左上锅位鸡油和骨膏都需要，则两者允许同时开启。
8. 只要整单里存在需要鸡油或骨膏、但当前不在左上角的锅位，就应在该轮开始前优先先把其中一个转到左上角，再执行它的加水与辅料。
