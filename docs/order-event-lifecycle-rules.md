# 订单催单、退单、转台事件规则

更新日期：2026-06-19

本文是 302（催单）、303（退单）、304（转台）的当前实现基线。历史草案与本文冲突时，以本文和代码测试为准。

订单当前态、alias 和事件审计以 Room 为单一事实源。旧 SharedPreferences JSON 仅用于首次升级导入，不再参与运行时写入。

## 1. 事件定位

事件先使用 `baseHash` 精确定位。302、304 精确定位失败后，可使用以下身份组合兜底：

1. 订单 alias（`ikmsOrder`、`posOrder`、转台前后的 alias）；
2. 锅型/根菜品 Code；
3. 事件时间不得早于订单创建时间或本地状态水位。

303 不使用 alias 兜底；`baseHash` 未安全命中时停止自动退单并告警。原则是宁肯不退，也不能错退同桌的另一锅。

POS 无法保证同桌、同锅型、同锅底顺序产生唯一业务 ID。存在多个完全相同候选锅时，不批量修改，也不按 alias 任意扩散；按根订单 `operateTime`、本地订单 ID 的稳定顺序，每个 POS 事件只消费一条。重复轮询同一事件时依靠事件根 ID 幂等，不得继续消费下一条。

锅底在 UI 中的展示顺序严格使用接口数组顺序。跨事件匹配不能假设锅底内容可以构成唯一身份，因为 POS 允许完全相同的多锅订单。

接口可能同时返回同一业务订单的 301、302、303、304 历史根记录。只有 301 是可进入订单队列的实体；302/303/304 是作用于实体的事件快照。同步完成后按接口根记录的真实 `operation` 清理旧版本误落库的事件快照，不能按内容相同直接合并真实 301 订单。

## 2. 事件时间

根订单 `operateTime` 是 301、302、303、304 统一的业务事件时间。`createTime`、`updateTime` 是接口记录写入时间，只用于诊断，不能覆盖 `operateTime`。催单、退单、转台成功后更新本地状态时间水位；早于水位的旧事件不得覆盖新状态或新桌号。

订单展示/创建时间与事件时间分开保存，不能用展示时间代替事件水位。

## 3. 催单（302）

- 催单状态使用独立字段 `isUrged`、`urgedAt`，不再用 `operation` 表示当前催单状态。
- 转台标记和催单标记可以同时存在，后发生的事件不能清掉另一类状态。
- `Pending`、`PendingWater` 可被催单。
- `Delayed` 被催单后立即恢复为 `PendingWater`，进入待加水队列。
- 已进入制作、待传锅、传锅或完成的订单不重新入队，也不生成重复订单。

## 4. 退单（303）

仅以下状态允许自动取消：

- `Pending`
- `PendingWater`
- `Delayed`

`Dispatching`、`Running`、`WaitingTransfer`、传锅中和 `Completed` 均不得自动取消。多个完全相同候选按 FIFO 只判断并消费第一条：第一条可取消才自动取消；第一条已经制作则停止自动退单并显示人工处理告警，不能跳过它去取消后面的待处理订单。

订单模式以“首条 PLC 相位命令成功写入”为物理执行边界。边界前的配方缺失弹窗可被退单终止；边界后，包括后续转锅弹窗期间，均视为已经完成部分加水，不得自动退单或返回待加水。

## 5. 转台（304）

- `tableCode` 是原桌号。
- `turnTableCode` 是新桌号。
- 本地订单定位成功后，用 `turnTableCode` 更新本地 `tableCode`。
- 新旧订单 alias 都保留，用于后续催单和退单继续命中同一锅。

## 6. 操作员告警

退单命中已制作记录或无法安全匹配时，告警进入独立的操作员告警队列，不依赖容易被同步日志覆盖的 `lastMessage`。操作员确认后，本轮相同告警不重复弹出；条件消失后若再次发生，则重新告警。

配方缺失弹窗期间收到有效退单时，关闭原弹窗并显示：“该订单已被退单，配方缺失处理已终止，设备未执行加水。”该告警只提供“我知道了”，旧的继续执行操作必须失效。

## 7. 必测场景

- 同桌同账单多锅：三类事件均只修改唯一目标锅。
- 同 alias、同锅型、同锅底顺序仍存在多条记录：按 `operateTime + ID` 每个事件只处理一条，重复轮询同一事件不继续处理下一条。
- 同特征记录第一条已制作、第二条待处理时收到 303：不得跳过第一条取消第二条，必须显示人工处理告警。
- 加水开始后收到 303：不得取消。
- 待传锅、传锅中、已完成收到 303：不得取消，并显示人工处理告警。
- `Delayed` 收到 302：恢复到待加水队列；收到 303：进入已取消。
- 先 304 后 302：桌号保持新桌号，同时保留催单状态。
- 先 302 后 304，且锅底方位发生旋转：仍保持一条订单，同时保留新桌号和催单状态。
- 新事件处理后再次轮询到旧事件：桌号和生命周期状态不得回退。
- 配方缺失弹窗期间收到 303：关闭配方弹窗，设备不动作，显示独立退单告警；旧确认按钮不能继续执行。
